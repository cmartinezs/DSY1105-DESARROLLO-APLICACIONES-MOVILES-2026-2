## Contrato didáctico de ejemplos

A partir de Semana 06, cada semana debe ofrecer **al menos cinco ejemplos guiados** que formen una progresión comprensible.

Cada `semana-XX/` debe tener un `README.md` índice que explique:

1. qué conceptos se trabajan;
2. en qué orden conviene recorrer los ejemplos;
3. qué idea nueva agrega cada ejemplo;
4. cómo experimentar con ellos.

Cada ejemplo debe:

- perseguir uno o pocos objetivos demostrativos claros;
- incluir contexto antes del código: **qué problema resuelve y por qué importa**;
- indicar qué observar al ejecutarlo;
- proponer al menos una modificación pequeña para experimentar;
- cerrar con una pregunta conceptual o criterio de comprensión;
- poder ejecutarse o trasladarse a un proyecto Compose sin depender de un lab completo;
- evitar instrucciones del tipo “anda y mira el código” como mecanismo principal de aprendizaje.

Los detalles de sintaxis o APIs pueden consultarse después. El material debe explicar primero el concepto general y el modelo mental.

Los ejemplos no sustituyen un laboratorio ni una etapa de PocketLog.

## Alcance retroactivo

Semanas 01–03 conservan por ahora su material actual. Su eventual adopción de este contrato se revisará por separado para no abrir un frente retroactivo mientras avanzamos con el contenido vigente.

Los ejemplos ya no viven dentro de `semanas/`: esa vertical queda reservada para contenido curricular.
