# Checklist operativo semanal · DSY1105

Este documento define el ciclo mínimo para preparar, ejecutar y cerrar cada semana de **DSY1105 · Desarrollo de Aplicaciones Móviles**.

No reemplaza la planificación institucional. Su función es mantener alineados cronograma, repo, portal web, Drive, avance real de la sección y evolución de PocketLog.

## 1. Antes de liberar la semana

- [ ] Confirmar semana curricular, fechas y feriados.
- [ ] Revisar cronograma institucional, material AVA y evaluaciones próximas.
- [ ] Revisar el avance real de la sección y las deudas de la semana anterior.
- [ ] Crear o reconciliar `semanas/semana-XX/`.
- [ ] Preparar guía(s) de contenido con una progresión explícita y comprensible.
- [ ] Preparar ejemplos Java/Kotlin o Kotlin cuando aporten transferencia real.
- [ ] Preparar práctica o laboratorio sin convertirlo en una receta de copia.
- [ ] Definir el incremento mínimo de PocketLog permitido por el contenido curricular.
- [ ] Actualizar `proyecto-formativo/guias/`, `pocketlog/` y `checkpoints/` cuando corresponda.
- [ ] Verificar enlaces entre repo, portal y Material Público.

## 2. Ruta mínima que debe ver el estudiante

La página principal debe responder:

1. **Qué aprender esta semana.**
2. **Qué ejemplo o práctica realizar.**
3. **Qué laboratorio corresponde.**
4. **Qué cambia en PocketLog.**
5. **Qué es obligatorio y qué es opcional.**
6. **Qué debería poder explicar al terminar.**

## 3. Durante las clases

- [ ] Registrar el avance efectivo de la sección.
- [ ] Mantener la estrategia forma explícita → comprensión → forma Kotlin más idiomática.
- [ ] No adelantar Android, arquitectura o APIs solo porque beneficien al diseño futuro.
- [ ] Ajustar PocketLog desde el último estado realmente alcanzado.
- [ ] Registrar dudas frecuentes y errores representativos.
- [ ] Mantener laboratorios breves y focalizados cuando el objetivo sea practicar un concepto puntual.

## 4. Cierre semanal

- [ ] Publicar o actualizar el resumen real.
- [ ] Actualizar el PocketLog vivo solo con contenido efectivamente habilitado.
- [ ] Crear checkpoint histórico únicamente cuando exista un estado funcional que valga la pena preservar.
- [ ] Reconciliar `semanas/`, `examples/`, `labs/`, `proyecto-formativo/`, `docs/` y `page/`.
- [ ] Comprobar que guía, proyecto vivo y checkpoint no compitan como fuentes.
- [ ] Revisar enlaces públicos.
- [ ] Registrar deuda pedagógica/técnica para la semana siguiente.

## 5. Criterio de calidad

Una semana está lista cuando un estudiante puede entrar al portal y responder:

- qué debo aprender ahora;
- qué debo practicar;
- qué parte de PocketLog debo tocar;
- dónde está el material;
- qué es opcional;
- qué debería poder explicar al terminar.

El objetivo no es producir la mayor cantidad posible de material, sino una experiencia de aprendizaje progresiva y navegable.
