# Checkpoints de PocketLog

Aquí se conservan estados históricos estables o hitos conceptuales del proyecto.

## Disponibles

- [Semana 01 · v0.1 conceptual](./semana-01/)
- [Semana 02 · v0.2 procedural](./semana-02/)
- [Semana 03 · v0.3 orientada a objetos](./semana-03/)

Un checkpoint sirve para **ver cómo queda PocketLog en un hito curricular**. No es el proyecto que continúa modificándose.

Cuando el avance real de una sección aún no confirma el hito completo, el checkpoint se interpreta como **estado objetivo de cierre** y `data/weekly/semana-XX.yml` conserva la verdad operacional.
